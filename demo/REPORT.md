# CORTEX — proof-of-life report

**What this is:** the first time the full CORTEX stack was stood up and run live. Until now the system was proven only by unit tests against PGlite + stubbed model calls — no container had come up, no real model had answered, no brief had ever been generated. This run closes that gap: a real Postgres, a real dashboard, a real on-box model, real audit data — all on **synthetic data**, at **$0** (no paid API key), on `127.0.0.1` only.

Everything here is reproducible with one command: **`scripts/bootstrap.sh`**.

---

## TL;DR

- ✅ `docker compose` brought up **db + migrate + dashboard** live — Postgres 16.14, all 8 tables migrated, dashboard on `127.0.0.1:3000`, auth gate enforced.
- ✅ A **26-item ground-truth-labeled synthetic inbox** (gmail/imap/whatsapp/calendar) ran through the **real pipeline** on a **local model** (Ollama `qwen2.5:7b-instruct`): 26 classified, 10 open loops, 1 Tomorrow Plan brief.
- ✅ **31 model calls, total cost `$0.000000`** — the local-first / cost-routing thesis, in real `api_calls` data.
- ✅ The **privacy boundary is demonstrated concretely**: stored `api_calls.input_summary` == the redaction-builder output (subject + sender + bounded snippet), never a body or chain — and it holds for the local model.
- ✅ **4 live-only bugs found and fixed** (smallest correct change each); `pnpm typecheck && pnpm test` and `pnpm db:check` green.
- ✅ **8 mobile (382px) screenshots** of every view + the audit inspector in `demo/screenshots/`.
- ✅ A **scored local-model benchmark** (`demo/benchmark.md`) turns the routing thesis into data.

## 4. The privacy boundary, made concrete (Phase D)

`packages/ai/src/redaction.ts` is the **only** constructor of model payloads, and `structuredCall` stores that exact object in `api_calls.input_summary` (same variable sent to the provider and written to the audit row — `sent == stored` by construction).

Proven on real audit data for the lease item:

```
api_calls.input_summary  =  {
  "source": "gmail",
  "snippet": "To hold your current rent we need the signed renewal back by 5pm tomorrow; the link expires after that.",
  "subject": "Signed lease renewal needed by tomorrow 5pm",
  "timestamp": "2026-07-07T18:02:49.821Z",
  "sender_display": "Marisol Vane (Brightgate Realty)",
  "sender_importance": 1
}
```

- The item's **full body at rest** is AES-256-GCM ciphertext (`v1:VlDhLibesHqTpqE5:/4bKU…:eltZ…`) — psql sees no plaintext.
- Across **all** `api_calls`: **0** rows contain `body_text` / `bodyText` / `body` / `raw` / a full `thread_context`.
- Every triage payload has exactly the 6 allowlist keys; **max snippet length = 131 ≤ 500** (`MAX_SNIPPET_CHARS`).
- **This holds for the local model** — the redaction layer builds the payload identically regardless of provider.

The `inspect/[id]` page renders this visually ("WHAT LEFT THE BOX"), and the newsletter items (classified by the pre-model heuristic) show **zero** `api_calls` — literally nothing left the box. See `demo/screenshots/cortex-07-inspect.png` and `cortex-08-inspect-nomodelcall.png`.

## 5. Runtime bugs found & fixed (Phase E)

Each fixed with the smallest correct change; tests added where they capture a genuine invariant. `pnpm typecheck && pnpm test` (all packages) and `pnpm db:check` green after every fix.

**Bug #1 — dashboard login couldn't authenticate (compose env gap).** The compose `dashboard` service passed `CORTEX_AUTH_SECRET` but not `CORTEX_OPERATOR_EMAIL` / `CORTEX_OPERATOR_PASSWORD_HASH`, so `authConfigured()` was false and the gate couldn't verify anyone. → Added both to the service env.

**Bug #2 — the scrypt hash `$` delimiters broke docker-compose interpolation.** `CORTEX_OPERATOR_PASSWORD_HASH=scrypt$SALT$HASH` — compose read `$SALT`/`$HASH` as undefined variables and blanked them, corrupting the hash. → The `.env` initializer `$$`-escapes the hash line (documented; the raw single-`$` form is only needed for the native-host fallback).

**Bug #3 — NULL category / Invalid-Date deadline from the local model.** Local models don't honor a tool schema's `enum`/`required` like the Claude tiers: `qwen2.5` occasionally omitted `category` (→ NOT-NULL violation, an item's triage lost) or returned a natural-language deadline like `"Friday"` (→ `new Date("Friday")` = Invalid Date). → `normalizeTriageResult()` in the AI tier coerces the output to a valid `TriageResult` (category ∈ vocabulary else `fyi`; deadline → ISO or null; urgency/confidence clamped). Covers triage **and** escalate. Unit-tested; re-running triage classified the previously-failed item cleanly (0 unclassified).

**Bug #4 — escalation was silently dead for the single-model (local) profile.** `getEscalationCandidates` excluded items already classified *by the escalate model id*. That's correct for the Anthropic profile (distinct Haiku/Sonnet/Opus ids) but, for the free/local profile — which uses **one** model for all tiers — every triaged item already had a row with that id, so **nothing was ever eligible**. → Re-keyed the guard on a tier-2 marker (`reasoning = 'escalated (tier-2)'`) so escalation fires once per item regardless of shared model ids. Verified live: escalated 9, append-only preserved (both passes retained), second run escalated 0 (idempotent).

**Finding A — auth fails *open* when unconfigured.** The `(secure)` layout only redirects `if (authConfigured())`; with `CORTEX_AUTH_SECRET` or the hash unset it renders views **unauthenticated**. Reasonable as a "setup mode" for a `127.0.0.1`-only single-user app, but it is fail-*open*, not fail-*closed*. Documented; the demo configures both so auth is enforced. (Candidate hardening: refuse to render in `NODE_ENV=production` when unconfigured.)

**Finding B — brief event times render in UTC.** A 09:30 Europe/Stockholm calendar event shows as "7:30 AM" (07:30Z) in the synthesis payload. Cosmetic; dates are correct. Noted for a follow-up (localize event times in `getTomorrowEvents`/synthesis).

**Reasoning-model hardening (from Bug #3's investigation).** The brief's default model, `qwen3:4b`, is a *reasoning* model: over Ollama's OpenAI-compat endpoint it dumps its chain into a separate `reasoning` field and spends the whole token budget "thinking" — returning **empty content, no tool_call** (`finish_reason: length`), so CORTEX's bounded structured calls get nothing. → Switched the pipeline to the non-reasoning `qwen2.5:7b-instruct` (same Ollama, same $0), and hardened `OpenAICompatProvider`: `extractJson` strips `<think>…</think>` blocks, and an empty structured response now throws a *diagnostic* error naming the reasoning-model cause instead of a cryptic parse failure. Unit-tested.

## 6. Scored local-model benchmark (the "wow")

On the **same** ground-truth-labeled inbox, each candidate local model is run through the **real provider seam** (`getProvider().structured` — tool-call → `json_object` fallback + the reasoning-model hardening), so every model is judged exactly as CORTEX would call it. Category accuracy is scored against the operator's expected label; cost comes straight from CORTEX's own pricing table.

| model | items | category acc | urgency ±1 | valid JSON | failures | avg latency | tokens | cost |
|---|---|---|---|---|---|---|---|---|
| `qwen2.5:7b-instruct` | 26 | **62%** | **92%** | **96%** | 1 | 3639 ms | 15874 | **$0.000000** |
| `gemma3:4b` | 26 | 58% | 88% | 92% | 2 | 3558 ms | 13938 | **$0.000000** |
| `qwen3:4b` (reasoning) | 6 | **0%** | — | **0%** | 6/6 | 30645 ms | 0 | $0.000000 |

**Routing recommendation (data-backed):**
- **Route CORTEX's bounded structured triage to a non-reasoning instruct model.** `qwen2.5:7b-instruct` is the pick: highest category accuracy (62%), highest urgency agreement (92%), and returns valid structured JSON 96% of the time — at **$0** and ~3.6 s/item on this box.
- `gemma3:4b` is a viable, slightly weaker fallback (58% / 88% / 92%) at the same $0 and latency — reasonable if RAM is tight.
- **Do NOT route structured/bounded calls to a reasoning model.** `qwen3:4b` returned **0% valid output** — it spends the whole `max_tokens` budget "thinking" (its answer lands in a separate `reasoning` field, `content` empty) — and did so at **~9× the latency** (30.6 s vs 3.6 s). This is the single most important local-model finding, and it's why the pipeline default was moved off the brief's suggested `qwen3`.
- Cost angle: every row is **$0** (local). The same triage on hosted Haiku would bill ~15.9k input-tokens/pass at Haiku rates — CORTEX's cost-routing thesis (cheap tier does the bulk of the work) is exactly what makes a fully-local run free.

62% on an 8-way classification against strict hand-authored labels is solid for a 7B model; several "misses" are defensible (e.g. `personal` vs `fyi`, `action_required` vs `financial`). Full per-item data: `demo/benchmark.json` · regenerate with `pnpm --filter @cortex/workers benchmark`.

```bash
scripts/bootstrap.sh
```

## 9. Still needs the operator (out of scope for an autonomous run)

Everything above is synthetic and needed no real credentials. To make CORTEX *yours*, these require you in the loop (all read-only, all gated):

- **Gmail / Google Calendar:** run `pnpm --filter @cortex/workers gmail:auth` against your own Google Cloud OAuth client (scope `gmail.readonly` / `calendar.readonly`). Set the OAuth app to **"In production"**, not "Testing," or Google expires the refresh token in 7 days.
- **Outlook.com:** `pnpm --filter @cortex/workers outlook:auth` (scope `IMAP.AccessAsUser.All`).
- **WhatsApp:** pair the isolated read-only bridge with a burner number (`docker compose --profile whatsapp --profile workers up`, scan the QR from its logs).
- **iMessage:** grant the macOS sidecar Full Disk Access to read `~/Library/Messages/chat.db`.

Turning any of these on is a strict, explicit opt-in — CORTEX stays **read-only in V1** (no send path anywhere; verified by grep across all adapters + sidecars).
